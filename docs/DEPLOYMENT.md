# Деплой и откат

## Переменные окружения

Обязательные для базового запуска: `BOT_TOKEN`, `DATABASE_URL` и административный ID (`ADMIN_ID` либо поддерживаемая проектом конфигурация списка). Для production также настройте `WEBHOOK_URL`, `SESSION_SECRET`, `ADMIN_LOGIN`, `ADMIN_PASSWORD` и `PORT`.

По функциям используются `REDIS_URL`, `TASK_BROKER_REDIS_URL`, `SUPABASE_URL`, `SUPABASE_KEY`, `STORAGE_CHANNEL_ID`, параметры Spotify, прокси и worker. Код читает именно `SUPABASE_KEY`. Если провайдер называет секрет `SUPABASE_SERVICE_ROLE_KEY`, его значение нужно безопасно передать в серверную переменную `SUPABASE_KEY`; браузеру этот ключ не отдаётся. Значения секретов в документации и Git не фиксируются.

## Production-последовательность

1. Зафиксировать текущую версию приложения и создать проверяемый backup Supabase.
2. Выполнить `013_admin_audit_fixes_precheck.sql` и изучить результат.
3. Применить `013_admin_audit_fixes.sql`.
4. Выполнить `013_admin_audit_fixes_verify.sql`.
5. Выполнить `014_yandex_partner_campaigns_precheck.sql`, устранить FAIL/WARN, применить `014_yandex_partner_campaigns.sql`, затем выполнить `014_yandex_partner_campaigns_verify.sql`.
6. Установить зависимости и проверить код:

```bash
npm ci
npm test
node --check index.js
node --check bot.js
npm run check:schema
```

7. Развернуть приложение на Render только после успешных проверок.
8. Выполнить ручные сценарии ниже и следить за логами/метриками.

Миграции не применяются и Render не деплоится автоматически этим репозиторием.

## Ручные сценарии

- вход в админку и отказ неавторизованному запросу;
- актуальный лимит Free/Plus/Pro после изменения `app_settings`, override и его удаление;
- создание, редактирование, выключение, архив, восстановление и защита системной кампании;
- JPG/PNG/WEBP/GIF и MP4, предпросмотр, замена, удаление, запрет SVG/HTML;
- успешный показ: Telegram → `yandex_promo_shown`; ошибка Telegram не меняет состояние;
- callback-клик, замена кнопки, дедупликация по `message_id`;
- временной cooldown, общий cooldown категории и максимум показов;
- совпадение статистики Dashboard и страницы рекламы;
- защищённое чтение `/support/file/:messageId`;
- обновление настроек на двух экземплярах через Redis Pub/Sub.

## Откат

При ошибке приложения сначала остановите новый deploy и верните предыдущий образ/commit. Схему не откатывайте автоматически. Rollback 013 и 014 применяются только после анализа и backup. Откат 014 выключает кампании, возвращает прежнее имя таблицы и сохраняет историю и Storage. Файлы Storage проверяются отдельно, поскольку Storage и PostgreSQL не образуют общую транзакцию.
